# 18. 案例 1: AI 代码助手

## 🎯 场景描述

你是一个正在学编程的学生。你想有一个 AI 助手能帮你：
- 写代码片段
- 解释代码在做什么
- 找 bug
- 把一种编程语言翻译成另一种

你手上有 OpenAI 和 Anthropic 的 API Key，但不想写代码——你只想打开一个软件就能用。

> 🎯 **核心方案**：用 CC-Switch 连接两个 AI，根据任务类型切换模型。

---

## 🏗️ 架构设计

```
┌──────────────────────────────────┐
│          你（开发者）              │
└──────────────┬───────────────────┘
               │ 鼠标点击切换模型
               ▼
┌──────────────────────────────────┐
│          CC-Switch               │
│      （桌面应用程序）              │
├──────────────────────────────────┤
│  模型列表：                       │
│  🔵 Codex（OpenAI Key）           │
│  🟣 Claude（Anthropic Key）       │
└──────────┬───────────┬───────────┘
           │           │
     ┌─────▼─────┐ ┌──▼──────────┐
     │  OpenAI   │ │  Anthropic  │
     │  (Codex)  │ │  (Claude)   │
     └───────────┘ └─────────────┘
```

整个系统非常简单——CC-Switch 就是中间那层。你不需要配置服务器、不需要写代码，只需要在 CC-Switch 中切换模型。

---

## 🎯 模型分工

| 任务类型 | 切换到哪个模型 | 为什么 |
|----------|--------------|--------|
| 写代码 | Codex | 代码生成能力最强 |
| 修 bug | Codex | 能精确定位问题 |
| 解释代码 | Claude | 解释更通俗易懂 |
| 代码审查 | Claude | 能给出有深度的改进建议 |
| 简单问题 | 随便 | 差别不大 |

---

## 🖥️ 实际操作流程

### 场景：写一个猜数字游戏

1. 打开 CC-Switch
2. 切换到 **Codex**（OpenAI）
3. 输入：
   ```
   用 Python 写一个猜数字游戏。
   电脑随机生成 1-100 的数字，玩家来猜。
   每次猜完提示"大了"或"小了"，直到猜对。
   ```
4. Codex 生成代码
5. 如果有不懂的地方，切换到 **Claude**（Anthropic）
6. 粘贴代码，输入：
   ```
   请解释这段代码的每一行在做什么
   ```
7. Claude 给出详细的代码解释

### 场景：代码翻译

1. 你已经写好了一段 JavaScript 代码
2. 切换到 **Codex**
3. 输入：
   ```
   把下面这段 JavaScript 代码翻译成 Python：
   [粘贴你的JS代码]
   ```
4. Codex 完成翻译
5. 切换到 **Claude**
6. 输入：
   ```
   检查下面两段代码的逻辑是否完全一致：
   [原始 JS 代码]
   vs
   [翻译的 Python 代码]
   ```
7. Claude 帮你做代码审查

---

## 💡 为什么不用一个模型包办一切？

前面的教程（14）讲过——不同模型各有所长。在代码助手场景中：

- Codex 的代码生成能力确实是目前最好的之一
- Claude 的长处是理解和解释，写出来的解释更自然

用一个模型也能用，但**用两个模型分工，效果更好**。

---

## 💡 要点总结

1. **不需要写任何代码**——CC-Switch 是桌面程序，所有操作靠点鼠标
2. **模型切换就是点一下的事**——在模型列表中选另一个就行
3. **关键技巧：Codex 写 → Claude 解释**——这个组合最实用
4. **API Key 只用填一次**——添加模型时填好，以后每次打开都能直接用
5. **记得设置用量上限**（教程 16）——防止 API 调用太多导致意外花费
