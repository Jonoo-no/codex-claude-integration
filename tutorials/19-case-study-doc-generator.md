# 19. 案例 2: 智能文档生成器

## 🎯 场景描述

你写了一段代码，现在需要：
- 给每个函数加上注释
- 写一个 README 文档
- 生成 API 说明给其他人看

你不想手动写这些文档——太花时间。你希望通过 AI 自动完成。

> 🎯 **核心方案**：用 Codex 分析代码结构，用 Claude 生成自然流畅的文档。

---

## 🏗️ 整体思路

```
你的代码
    ↓
切到 Codex → 分析代码，列出所有函数和类
    ↓
切到 Claude → 根据分析结果，生成文档
    ↓
完整文档输出
```

你不是让一个 AI 从头做到尾，而是**分两步走**：
1. Codex 做"阅读理解"（它最擅长读代码）
2. Claude 做"写作文"（它最擅长写文字）

---

## 🎯 模型分工

| 环节 | 用哪个 | 为什么 |
|------|--------|--------|
| 分析代码结构 | Codex | 代码理解最准 |
| 提取函数说明 | Codex | 能准确判断函数作用 |
| 写 README | Claude | 文字组织更自然 |
| 写 API 文档 | Claude | 格式清晰易读 |
| 写代码注释 | Codex 或 Claude | 都行，看偏好 |

---

## 🖥️ 实际操作流程

### 场景：给一个 Python 项目生成 README

假设你有一个 Python 文件 `calculator.py`：

```python
def add(a, b):
    return a + b

def subtract(a, b):
    return a - b

def multiply(a, b):
    return a * b

def divide(a, b):
    if b == 0:
        raise ValueError("Can't divide by zero")
    return a / b
```

**第一步：Codex 分析代码**

1. 打开 CC-Switch，切换到 **Codex**
2. 粘贴代码，输入：
   ```
   分析以下 Python 代码，列出每个函数的名字、参数、返回值和功能描述。
   用简洁的要点格式回答。
   
   [粘贴代码]
   ```
3. Codex 会输出类似：
   ```
   - add(a, b): 返回 a + b，加法函数
   - subtract(a, b): 返回 a - b，减法函数
   - multiply(a, b): 返回 a * b，乘法函数
   - divide(a, b): 返回 a / b，除法函数，b=0时抛异常
   ```

**第二步：Claude 生成文档**

1. 切换到 **Claude**
2. 把 Codex 的分析结果复制过来，输入：
   ```
   根据以下代码分析，帮我写一个 README.md 文件。
   包含：项目概述、安装说明（这个项目不需要安装）、
   函数说明、使用示例。
   
   [粘贴 Codex 的分析结果]
   ```
3. Claude 生成一份完整的 README 文档

---

## 🖥️ 场景二：生成 API 文档

如果你的代码是给别人调用的，需要更正式的 API 文档。

**第一步：Codex 提取接口信息**

切到 Codex，输入：
```
分析以下代码，提取所有公开的接口（函数和类）。
对每个接口列出：名称、参数类型、返回值类型、功能说明。
用表格格式输出。

[粘贴代码]
```

**第二步：Claude 生成正式文档**

切到 Claude，输入：
```
将以下接口信息整理成正式的 API 文档格式。
参考主流开源项目的文档风格。
包含每个接口的简要描述、参数说明、返回值说明、代码示例。

[粘贴 Codex 提取的信息]
```

---

## 💡 为什么分两步比一步好？

### 一步法（直接让一个 AI 写文档）

```
输入：代码 + "帮我写个文档"
输出：一份文档
```
缺点：AI 可能漏掉某些函数，或者对代码的理解不够准确。

### 两步法（Codex 分析 + Claude 写作）

```
第一步：Codex 专注分析代码 → 准确的结构信息
第二步：Claude 专注写文字 → 流畅自然的文档
```
优点：每个环节用最擅长的模型，结果更可靠。

---

## 💡 要点总结

1. **分两步，不要一步到位**——分析归分析，写作归写作
2. **Codex 做结构分析**——它看代码最准
3. **Claude 做文字输出**——它写的文档最好读
4. **第一步的输出是第二步的输入**——串起来就行
5. **这个思路适用于任何代码文档**——注释、README、API 文档、使用手册
