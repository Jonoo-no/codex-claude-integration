# 20. 案例 3: AI 模型管理方案

## 🎯 场景描述

你已经有了多个 API Key（可能 OpenAI 有好几个 Key，Anthropic 也有好几个）。你想合理地管理它们，避免混乱。

同时你可能会帮朋友或同事配置 CC-Switch——你想给他们一个清晰的操作指南。

> 🎯 **核心目标**：建立一套清晰的 Key 管理和模型切换习惯。

---

## 🏗️ 管理思路

### 单一 Key 的情况（大多数初学者）

```
你有一个 OpenAI Key + 一个 Anthropic Key
    ↓
在 CC-Switch 中各添加一个模型
    ↓
需要时切换
```

这是最简单的方案，够用。

### 多个 Key 的情况（团队 / 重度使用）

```
你有多个 Key（公司一个、个人一个、试用一个）
    ↓
在 CC-Switch 中分别添加，用清晰的命名区分
    ↓
按场景选择
```

---

## 📋 模型命名规范

在 CC-Switch 中添加多个模型时，用清晰的命名避免搞混：

| 命名建议 | 示例 |
|----------|------|
| 平台 + 用途 | `Codex-个人`、`Codex-公司` |
| 平台 + 模型版本 | `GPT-4o`、`GPT-4o-mini`、`Claude Sonnet` |
| 平台 + 场景 | `Codex-写代码用`、`Claude-分析用` |

### 不好的命名 vs 好的命名

| ❌ 不好的 | ✅ 好的 |
|----------|--------|
| `aaaa` | `Codex 写代码` |
| `test1` | `Claude Sonnet` |
| `mykey` | `GPT-4o-公司项目` |

好名字让你一眼就知道这是哪个 Key、用来干什么的。

---

## 🔀 模型切换策略

### 策略 A：按任务切换（推荐）

```
写代码 → Codex
解释代码 → Claude
分析文章 → Claude
优化代码 → Codex 先改，Claude 审查
```

### 策略 B：按成本切换

```
简单日常 → 便宜模型（GPT-4o-mini / Claude Haiku）
中等任务 → 标准模型（GPT-4o / Claude Sonnet）
高难度 → 最强模型（Claude Opus）
```

### 策略 C：按可用性切换

```
首选模型出问题 → 切到另一个平台
OpenAI 挂了 → 用 Anthropic
CC-Switch 出 bug → 用 Echo Bird
```

---

## 🔄 Key 生命周期管理

### 创建 Key
- 去 OpenAI / Anthropic 平台创建
- 创建后立刻保存到一个安全地方（密码管理器、加密笔记）

### 日常使用
- 填到 CC-Switch 中
- 定期查看用量（每周一次）

### Key 过期 / 废弃
- 去平台撤销旧 Key
- 创建新 Key
- 在 CC-Switch 中删除旧模型，添加新模型

### Key 泄露
- 立刻撤销（这是唯一正确的做法）
- 不要想着"改个密码"——API Key 没有密码，只能撤销

---

## 🛡️ 多用户场景

如果你要把 CC-Switch 推荐给朋友或同事：

### 给对方的最小操作指南

```
1. 去 https://platform.openai.com 注册，创建 API Key
2. 去 https://console.anthropic.com 注册，创建 API Key
3. 下载 CC-Switch：https://github.com/farion1231/cc-switch/releases
4. 打开 CC-Switch → 模型管理 → 添加模型 → 填入 Key
5. 开始使用
```

五步，不需要任何编程知识。

### 不要做的事

| ❌ 不要 | 为什么 |
|--------|--------|
| 把你的 Key 发给别人 | 别人会花你的钱 |
| 帮别人创建 Key 用你的账号 | Key 泄露责任在你 |
| 在公共电脑上保存 Key | 下一个用电脑的人能看到 |

---

## 💡 要点总结

1. **模型命名要清晰**——"Codex 写代码"比"test1"好一百倍
2. **便宜模型设为日常默认**——省钱第一
3. **两个平台都备好 Key**——互为备份
4. **每周看一次用量**——防止意外超支
5. **Key 泄露 = 立刻撤销**——没有商量余地
6. **推荐给别人时给五步指南**——清晰简洁
